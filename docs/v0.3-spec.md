# QA Buddy Recorder v0.3 — Техническое задание

## 1. Цель релиза

Версия **v0.3** переводит QA Buddy Recorder из базового recorder MVP в полноценный **QA evidence assistant**.

Основные цели:

- сделать интерфейс **русским по умолчанию**;
- сохранить поддержку English через i18n;
- улучшить структуру popup и работу с recorded session;
- расширить Steps / Network / Console / Screenshots;
- добавить editable Bug Report Builder;
- внедрить фирменный cat branding;
- добавить лёгкого pixel mascot, который не мешает основной QA-работе.

## 3. User stories

### US-01 — Русский интерфейс

**Как QA**, я хочу видеть Recorder на русском языке по умолчанию, чтобы быстро понимать controls и session state.

**Acceptance criteria:**

- default locale = `ru`;
- весь user-facing UI переведён;
- English доступен через switch;
- выбранный язык сохраняется в `chrome.storage.local`;
- после restart extension язык восстанавливается.

---

### US-02 — Сводка сессии

**Как QA**, я хочу видеть краткую Summary по recorded session.

**Acceptance criteria:**

Summary показывает:

- session status;
- duration;
- target domain;
- started at;
- finished at;
- steps count;
- HTTP / network issue count;
- console issue count;
- screenshots count.

---

### US-03 — Полный список шагов

**Как QA**, я хочу видеть все recorded steps, а не только последние.

**Acceptance criteria:**

Для каждого step отображается:

- порядковый номер;
- timestamp;
- action type;
- readable action label;
- URL / hostname;
- important flag;
- optional note.

Доступные действия:

- удалить step;
- отметить важным;
- добавить note;
- добавить manual step.

---

### US-04 — Network evidence

**Как QA**, я хочу быстро отфильтровать проблемные requests.

**Acceptance criteria:**

Network tab поддерживает:

- All;
- 4xx;
- 5xx;
- Network ERR;
- method badge;
- status code;
- endpoint / pathname;
- timestamp;
- copy request info.

В v0.3 допускается хранить только metadata без request / response body.

---

### US-05 — Console evidence

**Как QA**, я хочу видеть JavaScript errors отдельно от шагов.

**Acceptance criteria:**

Console tab отображает:

- `console.error`;
- uncaught exception;
- unhandled promise rejection;
- timestamp;
- source URL;
- sanitized message;
- copy action.

Sensitive values продолжают redaction перед storage.

---

### US-06 — Screenshot gallery

**Как QA**, я хочу видеть сделанные screenshots внутри recorded session.

**Acceptance criteria:**

- thumbnails grid;
- full-size preview;
- delete screenshot;
- mark screenshot as attachment;
- timestamp;
- source URL;
- screenshot создаётся только после explicit user action.

---

### US-07 — Bug Report Builder

**Как QA**, я хочу получить editable bug report после Stop.

**Поля:**

- Название;
- Preconditions;
- Steps to reproduce;
- Actual result;
- Expected result;
- Environment;
- Technical evidence.

**Acceptance criteria:**

- recorded steps автоматически попадают в Steps to reproduce;
- Network / Console summary автоматически добавляется в Technical evidence;
- поля можно редактировать;
- доступен Copy Markdown;
- доступен Copy plain text;
- доступен Export JSON;
- очищение session не происходит без explicit action.

---

## 4. UI architecture

Popup переводится на tab-based layout:

```text
┌─────────────────────────────────────────┐
│ 🐱 QA Buddy Recorder        ● ЗАПИСЬ    │
├─────────────────────────────────────────┤
│ Шаги 12 │ HTTP 2 │ Console 1 │ 📸 3    │
├─────────────────────────────────────────┤
│ Сводка | Шаги | Network | Console | 📸 │
├─────────────────────────────────────────┤
│                                         │
│            ACTIVE TAB CONTENT           │
│                                         │
├─────────────────────────────────────────┤
│        Primary session controls         │
└─────────────────────────────────────────┘
```

### UI requirements

- dark UI сохраняется;
- cyan остаётся primary accent;
- critical states используют red / amber только по назначению;
- primary CTA не должен теряться среди secondary controls;
- popup width ориентировочно 420–460 px;
- длинные lists используют internal scroll;
- toolbar на странице остаётся компактным.

## 5. Localization architecture

Создать:

```text
src/i18n/
├── ru.ts
├── en.ts
├── types.ts
└── index.ts
```

Пример API:

```ts
t("recorder.start")
t("session.steps")
t("network.errors")
```

### Правила

- UI text не хранить inline в React components;
- технические значения `GET`, `POST`, `4xx`, `5xx`, `JSON`, `HTTP` не переводить;
- bug report export должен использовать текущую locale;
- default locale = RU.

## 6. Pixel Mascot

Mascot — отдельный lightweight UI layer.

### Visual requirements

- маленький pixel-art cat;
- ориентировочный visual size: 24–40 px;
- не перекрывает controls;
- не должен занимать отдельный крупный panel;
- должен выглядеть как часть QA Buddy branding.

### Animation states

Standard mode:

- idle;
- blink;
- look around;
- wash;
- play with ball;
- short walk.

Fun mode:

- все Standard states;
- редкая litter-box animation.

### Behaviour rules

- random action interval: ориентировочно 25–90 sec;
- во время active recording mascot ведёт себя спокойнее;
- после Stop может быть активнее;
- при keyboard / button interaction не должен перекрывать UI;
- одна animation за раз;
- пользователь может отключить mascot;
- поддержать `prefers-reduced-motion`.

### Settings

- Показывать кота — on/off;
- Reduced motion — on/off / system;
- Fun mode — on/off.

### Technical approach

Предпочтительно:

- sprite sheet;
- CSS `steps()`;
- без тяжёлой animation dependency;
- animation state machine в React / TypeScript.

Структура:

```text
src/mascot/
├── Mascot.tsx
├── mascot.css
├── mascotState.ts
└── assets/
    └── cat-sprite.png
```

## 8. Data model v2

RecorderState расширяется.

Минимальный target:

```ts
type RecorderStep = {
  id: string;
  type: "page" | "click" | "input" | "manual";
  label: string;
  url: string;
  timestamp: number;
  note?: string;
  important?: boolean;
};

type RecorderScreenshot = {
  id: string;
  dataUrl: string;
  url: string;
  timestamp: number;
  attached?: boolean;
};

type BugReportDraft = {
  title: string;
  preconditions: string;
  actualResult: string;
  expectedResult: string;
  environment: string;
};

type RecorderSettings = {
  locale: "ru" | "en";
  mascotEnabled: boolean;
  reducedMotion: boolean;
  funMode: boolean;
};
```

Нужна backward compatibility с session state v0.2 через normalization / migration helper.

## 9. Privacy requirements

Обязательные правила:

- input values не сохранять;
- password values никогда не читать;
- query params с sensitive keys маскировать;
- console secrets redaction выполнять до storage;
- screenshot capture только explicit;
- screenshots не отправлять наружу;
- весь v0.3 работает local-only;
- clear session удаляет локальные session artifacts.

---

## 10. Non-functional requirements

### Performance

- popup должен открываться без заметной задержки;
- mascot не должен создавать постоянный high-frequency timer;
- animation должна быть CSS-based;
- capped storage сохраняется;
- large evidence lists не рендерить без ограничений.

### Reliability

- reload страницы не должен ломать active session;
- service worker restart не должен терять persisted state;
- malformed URL не должен падать в UI;
- ошибка screenshot capture должна показывать user-friendly message;
- empty session должна корректно отображаться.

### Accessibility

- buttons имеют `aria-label`;
- keyboard navigation доступна;
- contrast остаётся достаточным;
- reduced motion поддерживается;
- mascot не является источником обязательной информации.

## 12. Definition of Done

v0.3 считается готовой, когда:

- весь основной UI работает на RU и EN;
- RU включён по умолчанию;
- recording flow не регрессировал;
- tabs работают;
- evidence корректно отображается;
- bug report можно отредактировать и скопировать;
- JSON export работает;
- Markdown export работает;
- screenshots отображаются в gallery;
- logo отображается в extension;
- mascot можно включить / отключить;
- mascot не мешает controls;
- sensitive data masking сохранён;
- `npm run build` проходит;
- GitHub Actions CI = green;
- ручной smoke test Chrome пройден.

## 13. Smoke checklist v0.3

1. Установить clean build через Load unpacked.
2. Проверить default RU UI.
3. Переключить RU → EN → reload extension.
4. Запустить recording.
5. Проверить click / input / navigation steps.
6. Добавить manual step / note.
7. Создать screenshot.
8. Спровоцировать HTTP 4xx.
9. Спровоцировать console error.
10. Stop session.
11. Проверить Summary / Steps / Network / Console / Screenshots.
12. Отредактировать Bug Report Draft.
13. Copy Markdown.
14. Export JSON.
15. Проверить mascot on/off.
16. Проверить Standard / Fun mode.
17. Проверить Reduced motion.
18. Clear session.
19. Reload browser tab и extension.
20. Убедиться, что предыдущая session очищена.
